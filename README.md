# 이키즈라이브 번역 아카이브

`messages.db`의 멤버별 번역을 월별로 볼 수 있는 정적 사이트입니다.

## 실행

```sh
python3 scripts/export_data.py
python3 -m http.server 5173 --directory dist
```

http://localhost:5173 에서 확인합니다. DB 갱신 후 export 명령을 다시 실행하세요.

## GitHub Pages 배포

저장소: https://github.com/LoveLive-Archive-KR/ikizu_korean_translate_site

저장소의 `Settings → Pages → Build and deployment → Source`를 `GitHub Actions`로 설정합니다. `main` 브랜치에 push하면 `.github/workflows/pages.yml`이 `dist` 폴더만 배포합니다. 원본 DB는 업로드하지 않으며 이미 내보낸 `dist/data.json`을 사용합니다.

배포 주소: https://lovelive-archive-kr.github.io/ikizu_korean_translate_site/

번역을 갱신하려면 로컬에서 `python3 scripts/export_data.py`를 실행하고 변경된 `dist/data.json`을 커밋한 뒤 push하세요. 배포 결과는 저장소의 `Actions` 탭에서 확인합니다.

- 한국 시간(UTC+9) 기준 실제 게시일로 월을 분류합니다. 게시일은 X snowflake ID에서 계산하며 DB의 수집 시각과 구분합니다.
- `corrected_text`가 있으면 수정 번역을 우선합니다.
- 월별 탐색, 멤버 필터, 전체 기간 검색, 이름/계정/번역/원문 검색, 정렬, 원문 펼치기, 첨부 이미지, 원문 링크를 제공합니다.
- URL에 월, 멤버와 검색 조건을 보존합니다. 한 번에 20개씩 표시합니다.
- 원본 DB와 Discord 메시지/채널 ID는 배포하지 않습니다. 번역 데이터는 `dist/data.json`에 내보냅니다.
- 첨부 이미지는 원본 외부 URL을 사용하며 삭제 또는 접근 제한 시 열기 링크로 표시합니다.
- 자동 DB 동기화는 없습니다. 새 자료 반영에는 재내보내기와 재배포가 필요합니다.

## 프로필 사진

DB의 `twitter_handle`과 `character_name`을 기준으로 매칭합니다. 계정별 X 프로필 이미지를 [Unavatar](https://unavatar.io)로 가져와 `dist/avatars/`에 저장했습니다. 계정 매핑과 이미지 출처는 `scripts/avatar_sources.json`에 기록합니다. 이름은 [공식 멤버 소개](https://www.lovelive-anime.jp/lovehigh/member/?m=2)를 참고한 한국어 표기입니다. 사진은 저장 시점의 스냅샷이며 자동 갱신되지 않습니다. 새 계정 추가 시 매핑과 이미지를 함께 추가하세요.

DB에 `media_urls` 열이 없어도 내보낼 수 있습니다. 첨부 이미지 정보가 없는 DB에서는 게시물 이미지를 표시하지 않습니다.

## 시간순으로 이어 읽기

기본 화면은 가장 오래된 달부터 시작하는 한 줄 타임라인입니다. 모든 멤버의 글을 실제 게시 시간순으로 섞고 날짜 구분선을 표시합니다. 같은 시각의 글은 X 게시물 ID로 순서를 확정합니다. 20개씩 더 펼칠 때 기존 카드와 열린 원문을 유지하며 새 기록의 시작으로 이동합니다. 월의 마지막 기록을 펼치면 다음 기록이 있는 달로 이어 읽을 수 있습니다. 연도를 넘어 이동하며 DB에 글이 없는 달은 건너뜁니다. 멤버/검색 조건을 유지하고, 최신순에서는 반대 방향으로 이어갑니다. 전체 기간을 선택하면 월을 넘겨 한 타임라인에서 읽을 수 있습니다. `처음부터 읽기`는 필터를 초기화하고 모든 멤버의 첫 기록으로 돌아갑니다.

## 캘린더와 보기 단위

X 스타일의 한 열 피드에서 `월별`, `일별`, `전체 기록` 탭으로 범위를 전환합니다. 캘린더 날짜를 누르면 하루의 타임라인으로 이동하고, `이 달 전체 보기`는 캘린더의 월로 이동합니다. 월 입력으로 연도와 월을 직접 선택할 수도 있습니다. 캘린더의 월 입력과 좌우 버튼은 탐색 중인 달만 바꾸며, 기록이 없는 날짜도 선택해 빈 화면을 확인할 수 있습니다. 날짜별·월별 글 수는 선택한 멤버와 검색어를 함께 기준으로 계산합니다. 캘린더에서 방향키로 날짜 간 이동이 가능합니다.

일별 이어 읽기는 다음 기록이 있는 날로, 월별 이어 읽기는 다음 기록이 있는 달로 이동합니다. 상단의 이전/다음 버튼은 달력의 실제 하루/한 달씩 이동하므로 기록이 없는 기간도 확인할 수 있습니다. 모바일에서는 상단 `캘린더` 버튼으로 달력을 펼칩니다. 날짜/보기 단위를 URL에 보존하고, 게시물의 `링크 복사`는 해당 날짜와 게시물 위치를 포함한 링크를 복사합니다. 좋아요/답글 수는 원본 DB에 없으므로 표시하지 않습니다.

## 프로필로 멤버 선택

멤버 필터는 `전체` 버튼과 10명의 프로필 사진으로 제공합니다. 선택 상태는 테두리와 이름 색상, `aria-pressed`로 표시합니다. 월별/일별/전체 기록 범위와 검색·정렬을 유지한 채 선택한 멤버들의 글을 시간순으로 섞고 캘린더의 글 수를 함께 갱신합니다. 전체 버튼은 멤버 필터만 해제하며, 기존 `member` URL도 그대로 복원합니다. 모바일에서는 두 줄로 모든 멤버를 표시합니다.

## 이키즈라이브 색상

[프로젝트 공식 비주얼과 클럽 로고](https://digitalpr.jp/r/109574)의 블루·오렌지를 참고한 기본 테마입니다. 10명의 저장된 X 프로필 배경색을 프로필 테두리, 이름 옆 포인트, 상단 색상 띠에 반영했습니다. 멤버를 선택하면 탭·월 표시·캘린더·이어 읽기 버튼이 해당 멤버 색을 따라가고, 전체 선택은 기본 블루로 복귀합니다. 흰색은 회색 테두리로 구분합니다. 팔레트 출처와 샘플 값은 `scripts/palette_sources.json`에 기록했으며, 공식 디자인 시스템의 지정 HEX라고 주장하지 않습니다. 밝은 색의 글자·버튼은 읽기 쉬운 어두운 색을 사용합니다.

## Bootstrap 레이아웃

[Bootstrap 5.3.8](https://getbootstrap.com/docs/5.3/getting-started/introduction/)의 실제 12열 그리드, 폼, 버튼, 내비게이션 클래스와 Offcanvas를 사용합니다. 1200px 이상은 사이드바/피드/캘린더 3열, 768~1199px은 간결한 사이드바와 피드 2열, 작은 화면은 한 열입니다. 1200px 미만에서 캘린더는 포커스 관리·Esc·배경 닫기를 지원하는 Bootstrap 패널로 열립니다. 날짜를 선택하면 패널을 닫고 피드의 날짜 제목에 포커스를 돌려줍니다. 프레임워크 파일은 공식 배포본의 SHA-384를 검증한 뒤 `dist/vendor/bootstrap/`에 저장해 사용하며 MIT 라이선스를 함께 보존했습니다.

## 마지막 UX 정리

설명용 카드와 반복 안내, 피드의 중복 날짜 입력을 제거하고 날짜 선택은 캘린더에 모았습니다. 기록이 없는 월은 사이드바에서 생략하지만 캘린더에서 직접 선택한 월은 유지합니다. 같은 보기·기간을 재선택하면 펼친 글과 원문을 유지합니다. 보기 변경은 브라우저 뒤로/앞으로 가기로 복원하고, 검색 입력은 현재 기록을 갱신해 키 입력마다 히스토리를 추가하지 않습니다. 검색 결과가 없을 때는 검색 지우기로 복구합니다. 게시물 공유 링크는 날짜·글 위치만 포함해 다른 사람의 검색·멤버 필터에 영향을 받지 않습니다.

## 멤버 복수 선택

`전체` 버튼은 공식 X 계정의 파란 배경·흰색 심볼 로고(`dist/avatars/ikizulive_staff.jpg`)를 표시하며 선택된 멤버 필터를 해제합니다. 상단은 한국어 사이트명과 번역 사이트 표기를 사용해 필터 버튼과 구분합니다. 가로형 프로젝트 로고는 [공식 보도자료](https://digitalpr.jp/r/109574)의 이미지 배포본에서 가져와 `dist/brand/ikizulive-logo.png`에 보관했습니다. ©프로젝트 이키즈라이브!

프로필 사진을 눌러 멤버를 추가·해제합니다. 선택된 멤버들의 글은 날짜·검색·정렬 조건에 맞춰 한 타임라인으로 합칩니다. `전체`를 누르거나 마지막 선택을 해제하면 모든 멤버를 표시합니다. 캘린더와 월별 글 수도 같은 선택을 반영합니다. 한 명 선택은 해당 멤버 색, 여러 명 선택은 기본 프로젝트 색으로 표시하며 각 프로필의 선택 색은 그대로 유지합니다. URL의 반복 `member` 매개변수로 복수 선택을 보존하고 기존 단일 멤버 링크도 지원합니다. 뒤로·앞으로 가기에서도 선택 조합을 복원합니다.

## 인용 게시물


`> **@계정 인용:**` 또는 `> @계정 引用:` 다음에 이어지는 `>` 줄을 X 스타일 인용 카드로 표시합니다. 인용 밖의 본문과 줄바꿈을 분리해 유지하며 계정의 실제 프로필 사진을 사용합니다. DB 안에서 작성 계정과 인용 텍스트가 정확히 일치하는 이전 원글이 하나일 때만 실제 게시 시간과 X 원글 링크를 연결합니다. 원글 ID를 모르는 경우 시간이나 링크를 추측하지 않습니다. 알 수 없는 계정은 계정명과 문자 아이콘을 사용합니다. 텍스트를 HTML로 실행하지 않으며 일반 본문에는 영향을 주지 않습니다.

## AI 추천 실험

`experiment/ai-recommendations` 브랜치에서 검증한 뒤 `main`의 GitHub Pages 운영 사이트에 반영했습니다. 화면에는 `AI 추천 · 실험`으로 표시합니다.

```sh
npm ci
npm run recommendations:build
python3 -m unittest discover -s tests
python3 -m http.server 5174 --directory dist
```

원본 `messages.db`를 수정하지 않습니다. 이미 내보낸 2,457개 글 전체를 [다국어 E5 모델](https://huggingface.co/Xenova/multilingual-e5-small)로 로컬에서 분석하고, 모든 글 쌍의 의미 유사도를 전체 기간에 걸쳐 비교합니다. 게시 시점·공통 단서는 후보 순위를 조정하는 데 사용하며 특정 월이나 14일 범위로 제한하지 않습니다. 반복되는 미도리 자기소개와 공통 해시태그는 임베딩 입력에서 제외합니다. 모델은 지정된 리비전의 q8 ONNX 가중치를 첫 실행에 다운로드하며, 글 본문을 외부 AI API로 전송하지 않습니다. Node.js 20 이상이 필요합니다. `node_modules`와 모델·임베딩 캐시 `.cache`는 Git에 올리지 않습니다.

- 별도 `recommendations.db`: 원글 ID, 추천 대상 ID, 순서, 유사도, 근거 및 모델·원본 지문 등 생성 메타데이터를 저장합니다. 원본 DB와 조인은 글 ID 기준입니다.
- `dist/recommendations.json`: SQLite와 같은 추천 결과만 내보내 정적 사이트에서 사용합니다. 브라우저에서 AI를 실행하지 않습니다.
- 각 글의 `AI 추천 · 실험`을 펼치면 최대 3개 관련 글과 추천 이유가 나옵니다. 추천 링크는 기존 검색·멤버 필터를 제외한 해당 날짜·글 주소입니다.
- 추천은 실제 답글 관계의 확인이 아닙니다. 가까운 글은 `같은 날` 또는 `N일 이내`, 먼 글은 `다른 시기의 글`로 구분합니다. 최소 의미 유사도와 최상위 후보와의 차이를 함께 검사하며, 본문이 너무 짧거나 적절한 후보가 없으면 추천하지 않습니다. 유사도는 확률이 아니므로 화면에 정확도 백분율로 표시하지 않습니다.
- 추천 파일이 없거나 잘못됐거나 번역 JSON의 SHA-256과 맞지 않으면 추천을 생략하고 타임라인을 정상 표시합니다. 번역을 다시 내보낸 뒤에는 추천도 재생성해야 합니다.
- 초기 버전은 14일 범위와 엄격한 기준 때문에 초기 월에 추천이 없었습니다. 전체 기간 비교로 변경한 현재 버전은 기록이 있는 13개월 모두에서 추천하며, 1,682개 글에 3,987개의 연결이 있습니다. 초기 고교 생활·문화제·환경·오디션 등 샘플을 사람이 검토했습니다. 전체 연결의 정확성을 보장하는 정답 데이터는 없습니다.
